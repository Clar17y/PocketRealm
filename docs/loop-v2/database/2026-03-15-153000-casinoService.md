# Database Audit: casinoService

**Date:** 2026-03-15
**Service:** `apps/api/src/services/casinoService.ts` (389 lines, 6 exported functions)

## Prisma Models Touched
Direct: `RouletteRound`, `RouletteBet`, `Player`, `PlayerStats`

## Findings

### N+1 Queries
**1. `resolveRound` — per-bet update + per-winner gold update + per-winner achievement check (lines 135–188)**
For 10 bets from 5 players: 10 bet updates + 5 winner gold updates + 5 achievement checks (~15 queries each) = ~85 queries in worst case. Runs once per round (~60s), so moderate impact.

### Payload Bloat
**1. `getPublicBets` — no select on RouletteBet (line 290)** — full rows, uses 4 fields.

### Cache Issues
**Good Redis usage** — round state, result display window, distributed lock for resolution, phase tracking. Model pattern for real-time game state.

### Missing Indexes / Migration Risks
None.

## Suggested Fixes
1. Batch bet updates with raw SQL `UPDATE ... FROM VALUES`
2. Batch winner gold updates: `$executeRaw` with `unnest` for per-player amounts
3. Add `select` to `getPublicBets`
