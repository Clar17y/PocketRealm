# Database Audit: guildService

**Date:** 2026-03-15
**Service:** `apps/api/src/services/guildService.ts` (433 lines, 11 exported functions)

Direct: `Guild`, `GuildMember`, `GuildLog`, `Player`
Via sub-services: `TurnBank`, `PlayerStats`, `PlayerAchievement` (via achievements)

## Findings

### N+1 Queries

**1. `checkGuildAchievementsForAllMembers` — per-member achievement check loop (lines 421–431)**
Loops over ALL guild members, calling `checkAchievements` + `emitAchievementNotifications` for each. Each `checkAchievements` runs 2–5 queries. For a 20-member guild: **60–100 queries**. Fire-and-forget, but heavy.

```ts
const members = await prisma.guildMember.findMany({ where: { guildId }, select: { playerId: true } });
for (const { playerId } of members) {
  const newAchievements = await checkAchievements(playerId, { statKeys });
  await emitAchievementNotifications(playerId, newAchievements);
}
```

### Missing Indexes

**1. `Guild.level` — no index for `searchGuilds` `orderBy: { level: 'desc' }` (line 241)**
Guild search sorts by level descending. No index on `level` — requires full table scan + sort.

```ts
prisma.guild.findMany({
  where,
  orderBy: { level: 'desc' },  // no @@index([level])
  skip, take,
});
```

**2. `Guild.name` / `Guild.tag` — `contains` (ILIKE) can't use B-tree unique indexes (line 232)**
Substring search with `contains: query, mode: 'insensitive'` triggers sequential scan. Low priority — guild count is typically small.

### Payload Bloat

**1. `requireRole` — `include: { guild: true }` for role check (line 273)**
Fetches full `Guild` row (15+ columns) when only `membership.role` and `membership.guildId` are needed for the role check. The full guild is returned for downstream use, but most callers only use `guildId`.

```ts
prisma.guildMember.findUnique({
  where: { playerId },
  include: { guild: true },  // full 15-column row for role check
});
```

**2. `getPlayerGuild` — loads ALL guild members without pagination (lines 191–204)**
Single query loads every member of the guild with player data. For a 50-member guild: 50 member rows + 50 player joins in one response.

```ts
prisma.guildMember.findUnique({
  where: { playerId },
  include: {
    guild: {
      include: {
        _count: { select: { members: true } },
        members: {                              // ALL members, no limit
          include: { player: { select: { username: true, characterLevel: true } } },
        },
      },
    },
  },
});
```

**3. `guildMember.findUnique` in `createGuild` — no select for null check (line 146)**
Fetches full `GuildMember` row to check `!existing`.

### Cache Issues

**1. `getPlayerGuildId` — called 4+ times per combat (line 220)**
Already flagged in multiple prior audits. Returns a single `guildId` that only changes on join/leave/kick. Strongest guild cache candidate.

**No Redis usage anywhere in the service.**

### Migration Risks

None specific.

## Suggested Fixes

### Priority 1 — Cache `getPlayerGuildId`

```ts
const cacheKey = `guild:member:${playerId}`;
const cached = await redis.get(cacheKey);
if (cached !== null) return cached === '' ? null : cached;

const result = await prisma.guildMember.findUnique({ ... });
await redis.set(cacheKey, result?.guildId ?? '', 'EX', 300);
```

Invalidate on: join, leave, kick, disband. Saves 4+ queries per combat.

### Priority 2 — Batch guild achievement checks

```ts
const memberIds = members.map(m => m.playerId);
// Batch-fetch all stats and achievements for all members
const [allAchievements, allStats] = await Promise.all([
  prisma.playerAchievement.findMany({ where: { playerId: { in: memberIds } }, select: { playerId: true, achievementId: true } }),
  // ... batch resolve stats
]);
```

### Priority 3 — Slim `requireRole`

```ts
prisma.guildMember.findUnique({
  where: { playerId },
  select: { guildId: true, role: true },
});
```

Callers that need guild data can fetch it separately.

### Priority 4 — Add `@@index([level])` on Guild

```prisma
model Guild {
  @@index([level])
}
```

Covers `searchGuilds` ordering.
