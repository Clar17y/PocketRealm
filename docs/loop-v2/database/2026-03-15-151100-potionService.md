## Findings

### N+1 Queries

**1. `deductConsumedPotions` — per-template findFirst + update/delete loop (lines 87–101)**
For each consumed potion type: `findFirst` (full row) + `update`/`delete`. For 3 potion types: 6 queries.

```ts
for (const [templateId, count] of counts) {
  const item = await db.item.findFirst({ where: { ownerId: playerId, templateId } });
  if (item.quantity <= count) await db.item.delete({ where: { id: item.id } });
  else await db.item.update({ where: { id: item.id }, data: { quantity: item.quantity - count } });
}
```

### Missing Indexes

**1. `Item(ownerId, templateId)` — already identified**
Both `buildPotionPool` (joined filter on template.itemType) and `deductConsumedPotions` (filter by ownerId + templateId) need this index.

### Payload Bloat

**1. `buildPotionPool` — `include: { template: true }` for 3 fields (line 37)**
Uses `template.name`, `template.consumableEffect`, `template.id` — 3/14 template fields.

**2. `deductConsumedPotions` — `findFirst` without select (line 88)**
Fetches full `Item` row. Uses `id` and `quantity` only.
