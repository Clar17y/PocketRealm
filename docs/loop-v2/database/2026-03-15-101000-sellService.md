# Database Audit: sellService

**Date:** 2026-03-15
**Service:** `apps/api/src/services/sellService.ts` (91 lines, 2 exported functions)

## Prisma Models Touched

Direct: `Item`, `ItemTemplate`, `PlayerEquipment` (via equipment relation), `Player`

---

## Findings

### N+1 Queries

**1. `sellBulk` — per-item findUnique + delete loop (lines 66–80)**
Loops over `itemIds`, fetching each item individually (with 2 joins) then deleting. For 10 items: 10 findUnique + 10 delete + 1 player update = 21 queries.

```ts
for (const itemId of itemIds) {
  const item = await tx.item.findUnique({
    where: { id: itemId },
    include: { template: true, equipment: true },
  });
  // ... validation ...
  await tx.item.delete({ where: { id: itemId } });
}
```

Could be optimized to:
1. Single `findMany({ where: { id: { in: itemIds } }, ... })` — 1 query
2. Filter in JS
3. Single `deleteMany({ where: { id: { in: sellableIds } } })` — 1 query
4. Player gold update — 1 query
Total: 3 queries instead of 2N+1.

### Missing Indexes

No issues — all queries use PK lookups.

### Payload Bloat

**1. `include: { template: true, equipment: true }` — wider than needed (lines 28, 69)**
Both `sellItem` and `sellBulk` fetch full `ItemTemplate` (14 columns) and full `PlayerEquipment` relations. Used fields:
- `template.sellPrice` — 1 field out of 14
- `equipment.length > 0` — existence check, doesn't need full rows

```ts
tx.item.findUnique({
  where: { id: itemId },
  include: { template: true, equipment: true },
});
```

Could use:
```ts
select: {
  id: true, ownerId: true, quantity: true, rarity: true, inStash: true,
  isSoulbound: true, currentDurability: true, maxDurability: true,
  template: { select: { sellPrice: true } },
  equipment: { select: { slot: true } },  // just need count > 0
}
```

### Cache Issues

No Redis usage. No cache candidates — selling is a player-initiated action with no hot-path callers.

### Migration Risks

None.

## Query Patterns

### `sellItem` — 3 queries (in tx)

| Step | Query | Index |
|------|-------|-------|
| 1 | `item.findUnique({ id })` with template + equipment | PK |
| 2 | `item.delete` or `item.update` | PK |
| 3 | `player.update({ gold: { increment } })` with `select: { gold }` | PK |

Clean, minimal pattern. Good use of `select` on the player update.

### `sellBulk` — 2N+1 queries (in tx)

| Step | Query | Notes |
|------|-------|-------|
| 1–N | `item.findUnique` per item (with 2 joins) | N+1 |
| N+1–2N | `item.delete` per sellable item | N+1 |
| 2N+1 | `player.update({ gold: { increment } })` | Single |

## Suggested Fixes

### Priority 1 — Batch fetch + batch delete in `sellBulk`

```ts
const items = await tx.item.findMany({
  where: {
    id: { in: itemIds },
    ownerId: playerId,
    inStash: false,
    isSoulbound: false,
    equipment: { none: {} },
  },
  select: {
    id: true, quantity: true, rarity: true,
    currentDurability: true, maxDurability: true,
    template: { select: { sellPrice: true } },
  },
});

const sellable = items.filter(i => i.template.sellPrice);
const totalGold = sellable.reduce((sum, i) => sum + itemSellPrice(i) * i.quantity, 0);

await tx.item.deleteMany({ where: { id: { in: sellable.map(i => i.id) } } });
const player = await tx.player.update({
  where: { id: playerId },
  data: { gold: { increment: totalGold } },
  select: { gold: true },
});
```

Reduces from 2N+1 to 3 queries regardless of batch size.

### Priority 2 — Slim includes in `sellItem`

tx.item.findUnique({
