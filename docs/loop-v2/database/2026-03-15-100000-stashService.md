Direct: `Item`, `ItemTemplate`, `PlayerEquipment` (via equipment relation check)
Via sub-service: `PlayerEquipment` (via `getInventoryState` → `getUsedSlots`/`getPlayerCapacity`)

## Findings

### N+1 Queries

**1. `depositBatch` — per-item loop with findUnique + moveStackableItem (lines 122–131)**
For each item in the array: 1 `findUnique` (with 2 joins) + 1–3 `moveStackableItem` queries. For 10 items: 20–40 queries inside the transaction.

```ts
for (const itemId of itemIds) {
  const item = await tx.item.findUnique({
    where: { id: itemId },
    include: { template: true, equipment: true },
  });
  // ... validation ...
  await moveStackableItem(tx, item, item.quantity, true);
}
```

**2. `withdrawBatch` — per-item loop with findUnique + merge check + moveStackableItem (lines 145–163)**
Even heavier: each item does `findUnique` + conditional `findFirst` (merge check) + 1–3 `moveStackableItem`. For 10 items: 30–50 queries.

```ts
for (const itemId of itemIds) {
  const item = await tx.item.findUnique({
    where: { id: itemId },
    include: { template: true },
  });
  // ... merge check with findFirst ...
  await moveStackableItem(tx, item, item.quantity, false);
}
```

Both could batch-fetch items with a single `findMany({ where: { id: { in: itemIds } } })`.

### Missing Indexes

**1. `Item(ownerId, templateId, inStash)` — used by `moveStackableItem` and `listStash`**
Already identified in inventoryService audit. `moveStackableItem` calls `findFirst({ ownerId, templateId, inStash })` for stack merging. `listStash` calls `findMany({ ownerId, inStash: true })`.

```ts
// moveStackableItem — finds existing stack at destination
tx.item.findFirst({
  where: { ownerId: item.ownerId, templateId: item.templateId, inStash: targetInStash },
});

// listStash — all stashed items
prisma.item.findMany({
  where: { ownerId: playerId, inStash: true },
  include: { template: true },
});
```

### Payload Bloat

**1. `depositItem` — `include: { template: true, equipment: true }` for 2 checks (line 72)**
Fetches full `ItemTemplate` (14 columns) + all `PlayerEquipment` relations. Only uses `template.stackable` and `equipment.length > 0`.

```ts
tx.item.findUnique({
  where: { id: itemId },
  include: { template: true, equipment: true },  // full rows
});
// Uses: item.template.stackable, item.equipment.length > 0
```

**2. `listStash` — `include: { template: true }` with no select (line 171)**
Returns full `Item` + full `ItemTemplate` rows for all stashed items. The UI may not need all fields (e.g., `consumableEffect` JSON, `requiredSkill`, `requiredLevel`).

**3. `moveStackableItem` — `findFirst` without select (lines 19, 40)**
Fetches full `Item` row when only `id` and `quantity` are needed for the merge.

```ts
const existingTarget = await tx.item.findFirst({
  where: { ownerId: item.ownerId, templateId: item.templateId, inStash: targetInStash },
  // no select — full Item row
});
```

### Cache Issues

No Redis usage. No strong cache candidates — stash operations are player-initiated and infrequent.

### Migration Risks

None specific to this service.

## Suggested Fixes

### Priority 1 — Batch-fetch items in batch operations

Replace per-item `findUnique` with a single `findMany`:

```ts
// depositBatch
const items = await tx.item.findMany({
  where: { id: { in: itemIds }, ownerId: playerId, inStash: false },
  include: { template: { select: { stackable: true } }, equipment: { select: { slot: true } } },
});
// Then loop over already-fetched items for moveStackableItem
```

Reduces N `findUnique` queries to 1 `findMany`.

### Priority 2 — Add `select` to `moveStackableItem` findFirst

```ts
const existingTarget = await tx.item.findFirst({
  where: { ownerId: item.ownerId, templateId: item.templateId, inStash: targetInStash },
  select: { id: true, quantity: true },
});
```

### Priority 3 — Slim `depositItem` includes

```ts
tx.item.findUnique({
  where: { id: itemId },
  select: {
    id: true, ownerId: true, templateId: true, rarity: true,
    quantity: true, inStash: true,
    template: { select: { stackable: true } },
    equipment: { select: { slot: true } },  // only need count > 0
  },
});
```

### Priority 4 — Add `@@index([ownerId, templateId, inStash])` on Item

(Already recommended in inventoryService audit. Would benefit all `moveStackableItem` and `listStash` queries.)
