## State Issues

### 1. Zone history fetch has no cancellation guard
**Severity:** medium
**Lines:** 166-172

When the zone changes, `getChatHistory` is called but the promise result has no staleness check. If the player rapidly switches zones (e.g., multi-hop travel), an older zone's history response could arrive after a newer one and overwrite `zoneMessages` with stale data.

**Suggested Fix:** Add a cancelled/stale flag:
```tsx
useEffect(() => {
  if (currentZoneId === prevZoneIdRef.current) return;
  prevZoneIdRef.current = currentZoneId;
  if (!currentZoneId || !isAuthenticated) return;

  const socket = getSocket();
  if (socket.connected) socket.emit('chat:switch-zone', { zoneId: currentZoneId });

  setZoneMessages([]);
  setPinnedZone(null);
  const expectedZone = currentZoneId;
  getChatHistory('zone', `zone:${currentZoneId}`).then((res) => {
    if (res.data && currentZoneIdRef.current === expectedZone) {
      setZoneMessages(res.data.messages as ChatMessageEvent[]);
    }
  });
}, [currentZoneId, isAuthenticated]);
```

### 2. `joinCasino` fetches history without error handling
**Severity:** low
**Lines:** 222-233

`getChatHistory('casino', 'casino')` has no `.catch()`. If the API fails, the error is an unhandled rejection.

**Suggested Fix:** Add `.catch(() => {})` or a `.catch` that logs the error.
