# Frontend Audit: Gathering

**Component Audited:** `apps/web/src/components/screens/Gathering.tsx` (454 lines)
**Date:** 2026-03-15

---

## Accessibility

### 1. Filter selects lack labels
**Severity:** low
**Lines:** 238-264

The zone and resource type `<select>` elements have no `<label>` or `aria-label`. They use first-option text ("Zone: All", "Type: All") for visual context only.

**Suggested Fix:** Add `aria-label` to each:
```tsx
<select aria-label="Filter by zone" ...>
<select aria-label="Filter by resource type" ...>
```

### 2. Capacity progress bar lacks ARIA
**Severity:** low
**Lines:** 320-325

The node capacity bar has no `role="progressbar"` or ARIA attributes. The text below (`remaining / max remaining`) provides numeric context.

**Suggested Fix:** Add `role="progressbar"` + `aria-valuenow={node.remainingCapacity}` + `aria-valuemax={node.maxCapacity}` + `aria-label={`${node.name} remaining capacity`}`.

## UX Issues

### 1. Start button disabled condition is a dense inline expression
**Severity:** low
**Lines:** 440

```tsx
disabled={isOverEncumbered || isRecovering || selectedBlockedByFull || turnInvestment[0] > availableTurns || turnInvestment[0] < sliderMin || nodesLoading || Boolean(nodesError) || skillLevel < selectedNode.levelRequired || currentZoneId !== selectedNode.zoneId}
```

Eight boolean conditions in a single inline expression. While functional, it makes debugging which condition is blocking the button difficult.

**Suggested Fix:** Compute into a named variable with the reason:
```tsx
const gatherDisabledReason = isOverEncumbered ? 'Over-Encumbered'
  : isRecovering ? 'Recover First'
  : selectedBlockedByFull ? 'Backpack Full'
  : turnInvestment[0] > availableTurns ? 'Not enough turns'
  : currentZoneId !== selectedNode.zoneId ? 'Wrong zone'
  : null;
```
This is partially done for the button label (line 444) but not for the disabled prop itself.
