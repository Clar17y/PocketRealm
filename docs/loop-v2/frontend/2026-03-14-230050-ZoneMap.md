# Frontend Audit: ZoneMap

**Component Audited:** `apps/web/src/components/screens/ZoneMap.tsx` (710 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. Zone buttons lack meaningful accessible names
**Severity:** medium
**Lines:** 529-669

Each zone renders as a `<button>` but its accessible name is derived from mixed content — images, spans, icon elements. For undiscovered zones, the only text content is "?". Screen readers produce garbled or unhelpful announcements like "question mark Star Star Star Hourglass 50".

**Suggested Fix:** Add `aria-label` to each zone button:
```tsx
<button
  aria-label={isUndiscovered ? 'Undiscovered zone' : `${zone.name}, difficulty ${zone.difficulty}, ${zone.travelCost} turn travel cost${isCurrent ? ', current location' : ''}`}
  ...
>
```

### 2. Difficulty stars have no text alternative
**Severity:** low
**Lines:** 323-326, 626-636

Difficulty is communicated through 1-5 star icons with no `aria-label` or screen-reader text. Both the detail panel and zone nodes use this pattern.

**Suggested Fix:** Add `aria-label={`Difficulty ${zone.difficulty} of 5`}` to the star container div, and `aria-hidden="true"` to individual star icons.

### 3. Exploration progress bar lacks ARIA progressbar role
**Severity:** low
**Lines:** 383-388

The exploration progress bar is a purely visual div with no `role="progressbar"`, `aria-valuenow`, `aria-valuemin`, or `aria-valuemax`.

**Suggested Fix:** Add ARIA attributes to the outer bar:
```tsx
<div role="progressbar" aria-valuenow={Math.floor(percent)} aria-valuemin={0} aria-valuemax={100} ...>
```

## Component Duplication

### 1. `maxRowWidth` computed 3 separate times
**Severity:** medium
**Lines:** 171-176 (zonePositions), 194-199 (svgSize), 514-518 (render loop)

The same `rowZones.length * NODE_W + (rowZones.length - 1) * COL_GAP` loop over all tier rows is repeated in three places. The render-time computation (lines 514-518) is the worst — it runs inside a `.map()`, making it O(n²) when it should be O(1) since the value is already computed.

**Suggested Fix:** Compute `maxRowWidth` once in a `useMemo` and pass it through:
```tsx
const maxRowWidth = useMemo(() => {
  let max = 0;
  for (const [, rowZones] of tierRows) {
    const w = rowZones.length * NODE_W + (rowZones.length - 1) * COL_GAP;
    if (w > max) max = w;
  }
  return max;
}, [tierRows]);
```
Then reference `maxRowWidth` in `zonePositions`, `svgSize`, and the render loop instead of recalculating.

### 2. Difficulty stars pattern duplicated
**Severity:** low
**Lines:** 323-326, 626-636

Both the detail panel and zone node render the same `Array.from({ length: Math.min(difficulty, 5) }).map(Star)` pattern. Minor — could extract a `<DifficultyStars level={n} />` component.

## State Issues

### 1. `maxRowWidth` recalculated O(n²) during render
**Severity:** medium
**Lines:** 514-518

Inside the `tierRows.map()` render loop, `maxRowWidth` is recalculated by iterating all `tierRows` for every row. With 5 tiers of zones, this iterates `5 * 5 = 25` times instead of once. The value is static for a given `tierRows` and is already available from `svgSize.width`.

**Suggested Fix:** Replace lines 514-518 with `const maxRowWidth = svgSize.width;` (since `svgSize.width` already computes `Math.max(maxRowWidth, NODE_W)`).

## UX Issues

### 1. Zone nodes and detail panel use extensive inline styles
**Severity:** low
**Lines:** 304-313, 544-574, 577-589, 606-619, 640-652, 657-664

The zone map uses inline `style={{...}}` objects extensively instead of Tailwind classes, unlike the rest of the app. While functional, this creates inconsistency and makes the code harder to maintain. The detail panel (lines 304-313) uses inline style for background, border, borderRadius, padding, and boxShadow that could all be Tailwind classes.

**Suggested Fix:** Convert inline styles to Tailwind where possible. For dynamic values (position, width), inline styles are appropriate, but static properties like `borderRadius: 8`, `padding: 12`, `background` can use Tailwind.
