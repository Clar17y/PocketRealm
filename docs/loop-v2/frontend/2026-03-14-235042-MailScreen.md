# Frontend Audit: MailScreen

**Component Audited:** `apps/web/src/components/screens/MailScreen.tsx` (627 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. Tab buttons lack ARIA tab roles
**Severity:** medium
**Lines:** 262-280

The Inbox/Sent/Compose tab buttons have no `role="tablist"`, `role="tab"`, or `aria-selected`.

**Suggested Fix:** Wrap in `<div role="tablist">` and add `role="tab"` + `aria-selected` to each button. Or simply use the `SubNav` component which is already imported but unused (see Component Duplication #1).

### 2. Delete button uses `title` instead of `aria-label`
**Severity:** medium
**Lines:** 418-424

The `×` delete button uses `title="Delete"` which screen readers don't reliably announce. The button's text content is just `×`.

**Suggested Fix:** Replace `title` with `aria-label`:
```tsx
<button aria-label="Delete mail" ...>&times;</button>
```

### 3. Compose form labels not linked to inputs
**Severity:** low
**Lines:** 486-498, 503-516, 521-534

The `<label>` elements for To, Subject, and Message aren't linked via `htmlFor`/`id`. Clicking the label doesn't focus the corresponding input.

**Suggested Fix:** Add matching `htmlFor`/`id` pairs:
```tsx
<label htmlFor="mail-recipient">To</label>
<select id="mail-recipient" ...>
```

## Component Duplication

### 1. `SubNav` imported but not used — tabs hand-rolled
**Severity:** low
**Lines:** 8, 262-280

`SubNav` is imported at line 8 but the tab rendering at lines 262-280 duplicates its behavior manually with the same gold active styling pattern. This is inconsistent with other screens (Quests, FriendsScreen, etc.) that use `SubNav`.

**Suggested Fix:** Replace the manual tab rendering with `SubNav`:
```tsx
<SubNav
  tabs={tabs.map(t => ({ id: t.id, label: t.label, badge: t.count }))}
  activeId={activeView}
  onSelect={(id) => handleTabSwitch(id as MailView)}
/>
```
This removes ~18 lines and ensures consistent tab styling across the app. If `SubNav` doesn't support the `(count)` suffix, the count could be incorporated into the label string.

## State Issues

### 1. `initialRecipientId` only used as initial value, not synced on change
**Severity:** medium
**Lines:** 39-41, 59

```tsx
const [activeView, setActiveView] = useState<MailView>(
  initialRecipientId ? 'compose' : 'inbox',
);
// ...
const [composeRecipientId, setComposeRecipientId] = useState(initialRecipientId ?? '');
```

If the parent navigates to mail from a different friend profile (changing `initialRecipientId`), the compose recipient won't update because `useState` only reads the initial prop value.

**Suggested Fix:** Add a sync effect:
```tsx
useEffect(() => {
  if (initialRecipientId) {
    setComposeRecipientId(initialRecipientId);
    setActiveView('compose');
  }
}, [initialRecipientId]);
```

### 2. Sent tab lazy-load check uses `sent.length === 0`
**Severity:** low
**Lines:** 203-205

```tsx
if (view === 'sent' && sent.length === 0) {
  void loadSent(sentPage);
}
```

If the user genuinely has zero sent mail, switching to the Sent tab won't trigger a re-fetch since the condition is always true. The first load correctly populates the empty array, but the check can't distinguish "not yet loaded" from "loaded but empty".

**Suggested Fix:** Use a `sentLoaded` boolean ref:
```tsx
const sentLoadedRef = useRef(false);
// ...
if (view === 'sent' && !sentLoadedRef.current) {
  sentLoadedRef.current = true;
  void loadSent(sentPage);
}
```

## UX Issues

### 1. Delete mail has no confirmation dialog
**Severity:** medium
**Lines:** 143-161, 418-424

Clicking the `×` button immediately deletes the mail. Mail deletion is permanent — there's no undo or trash folder. The delete button is small and positioned near the mail row, making accidental clicks easy on mobile.

**Suggested Fix:** Add a confirmation step. Options:
- Use `ConfirmModal` from `components/common/`
- Or add an inline "Are you sure?" state per row (like `[confirmDeleteId, setConfirmDeleteId]`)

### 2. Success message auto-navigates away from compose
**Severity:** low
**Lines:** 180-183

After sending mail, the view auto-switches to "sent" after 1.5 seconds. This removes user control — if they want to compose another mail to the same recipient, they must navigate back.

**Suggested Fix:** Show the success message but stay on compose, with a "View sent mail" link instead of auto-navigating. Or at minimum, extend the delay and add a way to cancel the navigation.
