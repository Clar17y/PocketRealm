# Frontend Audit: TalentTree

**Component Audited:** `apps/web/src/components/screens/TalentTree.tsx` (345 lines)
**Date:** 2026-03-15

---

## Accessibility

### 1. Tree tab buttons lack ARIA tab roles
**Severity:** low
**Lines:** 161-180

The Melee/Ranged/Magic/Survival tab buttons have no `role="tablist"`, `role="tab"`, or `aria-selected`. Lower severity than most screens since the buttons have clear text labels and visible selection state.

**Suggested Fix:** Wrap in `<div role="tablist">` and add `role="tab"` + `aria-selected={isActive}`.

---

## Component Duplication

No issues found. The component is well-structured with clean helper functions (`groupNodesByTier`, `countTierAllocations`, `canAllocate`). The node card rendering is specific enough to not warrant extraction.

---

## State Issues

### 1. Style duplicates same value for both locked and unlocked description
**Severity:** low
**Lines:** 267

```tsx
style={{ color: isLocked ? 'var(--rpg-text-secondary)' : 'var(--rpg-text-secondary)' }}
```

Both branches of the ternary produce the same color. The ternary is dead code — likely a leftover from when locked/unlocked descriptions had different colors.

**Suggested Fix:** Simplify to `style={{ color: 'var(--rpg-text-secondary)' }}` or just use the class `text-[var(--rpg-text-secondary)]` directly.

---

## UX Issues

No issues found. The component properly uses `ConfirmModal` for respec (unlike Forge/Templates which lack confirmation for destructive actions), shows clear lock reasons for each node, and uses the `SkillTreeTutorial` for onboarding. The tier gate system with "Need 2+ allocations in Tier N" messaging is well-implemented.
