# Frontend Audit: Equipment

**Component Audited:** `apps/web/src/components/screens/Equipment.tsx` (668 lines)
**Date:** 2026-03-14

## Accessibility

### 1. Close buttons lack aria-label
**Severity:** medium
**Lines:** 233-238, 497-502

Both the slot selection modal and repair-all modal use `<X>` icon buttons with no `aria-label`.

**Suggested Fix:** Add `aria-label="Close"` to both close buttons.

### 2. Equipment slot buttons lack descriptive aria-labels
**Severity:** medium
**Lines:** 152-198

When an item is equipped, the `<button>` shows only an image (via `ItemIcon`) — no text. Screen readers can't communicate what slot this is or what item is in it. Empty slots show the label text, which is better but still lacks context.

**Suggested Fix:** Add `aria-label` to each slot button:
```tsx
<button
  aria-label={item ? `${position.label}: ${item.name}${item.durability <= 0 ? ' (broken)' : ''}` : `${position.label}: empty`}
  ...
>
```

### 3. Broken item "!" badge has no screen reader text
**Severity:** low
**Lines:** 170-173

The red "!" badge indicating broken equipment is a visual-only indicator. Screen readers see just "!" with no context.

**Suggested Fix:** Add `aria-hidden="true"` to the badge div (since the `aria-label` on the parent button from fix #2 would cover it), or add `<span className="sr-only">Broken</span>`.

## Component Duplication

### 1. Stat comparison diff computation verbose and inline
**Severity:** medium
**Lines:** 358-379

For each candidate item in the equip modal, 6 stat values are individually computed for both current and candidate items, then diffed. This is 12 `totalStatValue()` calls per candidate, done inline in the render `.map()`.

**Suggested Fix:** Extract a helper:
```tsx
function computeStatDiffs(
  currentBase: Record<string, unknown> | undefined,
  currentBonus: Record<string, unknown> | null | undefined,
  nextBase: Record<string, unknown> | undefined,
  nextBonus: Record<string, unknown> | null | undefined,
): Array<{ key: string; diff: number }> {
  const stats = ['attack', 'armor', 'magicDefence', 'health', 'dodge', 'accuracy'];
  const labels = ['Attack', 'Armor', 'Magic Def', 'HP', 'Dodge', 'Accuracy'];
  return stats.map((stat, i) => ({
    key: labels[i],
    diff: totalStatValue(nextBase, nextBonus, stat) - totalStatValue(currentBase, currentBonus, stat),
  })).filter(d => d.diff !== 0);
}
```

### 2. Bonus stats rendering duplicated
**Severity:** medium
**Lines:** 325-342, 644-658

Both the modal's "Currently Equipped" section and the equipped items list render the same bonus stats pattern: filter `bonusStats` entries for non-zero numbers, map to colored `<span>` with `formatSignedStatValue`. Identical logic.

**Suggested Fix:** Extract a `<BonusStatsBadges bonusStats={item.bonusStats} />` component:
```tsx
function BonusStatsBadges({ bonusStats }: { bonusStats: Record<string, unknown> | null | undefined }) {
  const entries = Object.entries(bonusStats ?? {})
    .filter((e): e is [string, number] => typeof e[1] === 'number' && e[1] !== 0);
  if (entries.length === 0) return null;
  return (
    <div className="flex flex-wrap gap-x-2 gap-y-1 text-[8px] font-pixel">
      {entries.map(([stat, value]) => (
        <span key={stat} className={value < 0 ? 'text-[var(--rpg-red)]' : 'text-[var(--rpg-green-light)]'}>
          {formatSignedStatValue(stat, value)} {prettyStatName(stat)}
        </span>
      ))}
    </div>
  );
}
```

## State Issues

### 1. Current item stats recomputed per candidate inside `.map()`
**Severity:** medium
**Lines:** 358-363

`totalStatValue(currentItem?.baseStats, ...)` is called 6 times for every candidate item, but `currentItem` doesn't change between iterations. These 6 values should be computed once before the `.map()`.

**Suggested Fix:** Move current item stat computation before the candidates loop:
```tsx
const currentStats = {
  attack: totalStatValue(currentItem?.baseStats, currentItem?.bonusStats, 'attack'),
  armor: totalStatValue(currentItem?.baseStats, currentItem?.bonusStats, 'armor'),
  // ... etc
};
// Then inside .map():
const diffs = [
  { key: 'Attack', diff: nextAttack - currentStats.attack },
  // ...
```

## UX Issues

No issues found. The component correctly uses `DURABILITY_CONSTANTS` for repair costs (unlike the hardcoded values in Inventory.tsx), provides a confirmation modal for Repair All, and properly disables buttons during busy state. The stat comparison diffs when equipping are a nice touch.
