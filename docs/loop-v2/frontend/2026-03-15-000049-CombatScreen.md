# Frontend Audit: CombatScreen

**Component Audited:** `apps/web/src/app/game/screens/CombatScreen.tsx` (619 lines)
**Date:** 2026-03-15

---

## Accessibility

### 1. Tab buttons lack ARIA tab roles
**Severity:** medium
**Lines:** 297-331

The Encounters/History/Boss History tab buttons have no `role="tablist"`, `role="tab"`, or `aria-selected`.

**Suggested Fix:** Wrap in `<div role="tablist">` and add `role="tab"` + `aria-selected` to each button, or use `SubNav`.

### 2. Filter selects lack labels
**Severity:** low
**Lines:** 476-512

The sort, zone filter, and mob filter `<select>` elements have no associated `<label>` or `aria-label`. The first `<option>` in each provides some context ("Sort: Most Dangerous", "Zone: All", "Family: All").

**Suggested Fix:** Add `aria-label` to each select:
```tsx
<select aria-label="Sort encounters by" ...>
<select aria-label="Filter by zone" ...>
<select aria-label="Filter by mob family" ...>
```

### 3. Last combat collapse button lacks aria-expanded
**Severity:** low
**Lines:** 405-424

The button toggling combat log visibility uses `▶`/`▼` text but no `aria-expanded` attribute.

**Suggested Fix:** Add `aria-expanded={!lastCombatCollapsed}` to the button.

## Component Duplication

### 1. Tab buttons hand-rolled instead of SubNav
**Severity:** low
**Lines:** 297-331

Three tab buttons with the same active/inactive gold styling pattern used across many screens. Could use `SubNav` for consistency.

**Suggested Fix:** Replace with:
```tsx
<SubNav
  tabs={[
    { id: 'encounters', label: 'Encounters' },
    { id: 'history', label: 'History' },
    { id: 'bossHistory', label: 'Boss History' },
  ]}
  activeId={activeView}
  onSelect={(id) => setActiveView(id as typeof activeView)}
/>
```

## State Issues

### 1. `buildShareText` has unnecessary `mobMaxHp` dependency
**Severity:** low
**Lines:** 186-196

`mobMaxHp` is listed in the `useCallback` dependency array but isn't used inside `buildShareText` — the function passes `displayedFight.combatantBMaxHp` directly. This causes unnecessary re-memoization when `mobMaxHp` changes.

**Suggested Fix:** Remove `mobMaxHp` from the dependency array:
```tsx
}, [lastCombat, displayedFight, outcomeLabel, playerMaxHp]);
```

## UX Issues

### 1. Strategy modal uses hardcoded color fallbacks inconsistent with theme
**Severity:** medium
**Lines:** 217-260

The strategy selection modal uses hardcoded fallback values like `var(--rpg-gold,#c8a84e)` and `var(--rpg-light-dim,#a0a0b0)` that don't appear elsewhere in the codebase. It also uses raw `<button>` elements with inline styling instead of `PixelButton` or themed components.

**Suggested Fix:** Replace with standard theme variables and `PixelButton`:
```tsx
<ModalOverlay onClose={() => setStrategyModalSite(null)}>
  <PixelCard className="max-w-sm w-full">
    <h3 className="text-[var(--rpg-gold)] font-bold text-lg mb-1">Choose Strategy</h3>
    <p className="text-[var(--rpg-text-secondary)] text-sm mb-4">...</p>
    <div className="flex flex-col gap-3">
      <PixelButton variant="gold" className="w-full text-left" ...>
        Full Clear
      </PixelButton>
      <PixelButton variant="secondary" className="w-full text-left" ...>
        Room by Room
      </PixelButton>
      <PixelButton variant="secondary" size="sm" onClick={() => setStrategyModalSite(null)}>
        Cancel
      </PixelButton>
    </div>
  </PixelCard>
</ModalOverlay>
```
This ensures the modal matches the app's design system and renders correctly across theme variations.
