# Frontend Audit: CombatLog

**Component Audited:** `apps/web/src/components/screens/CombatLog.tsx` (214 lines)
**Date:** 2026-03-15

> Note: This component appears to be a legacy/unused combat display. The active combat system uses `CombatPlayback` + `CombatLogEntry` + `CombatRewardsSummary`. This file's `CombatLogProps` interface (round-based messages, `status: 'ongoing'`) doesn't match the current API response shape. It may be dead code.

---

## Accessibility

### 1. Dropped item icons use `title` instead of `aria-label`
**Severity:** low
**Lines:** 145-153

Item drop icons in the victory modal use `title={item.name}` but no `aria-label`. Screen readers see raw emoji content.

**Suggested Fix:** Add `aria-label={item.name}` and `role="img"` to each item div.

---

## Component Duplication

### 1. Victory/defeat modals duplicate patterns from CombatPlayback
**Severity:** low
**Lines:** 104-168, 171-211

The victory and defeat modals here duplicate the outcome display pattern from `CombatPlayback` (lines 316-338). Since this component may be unused, the duplication is moot — but if it's kept, it should use `CombatRewardsSummary` for rewards display.

---

## State Issues

No issues found. This is a pure presentational component with no state — all data comes from props.

---

## UX Issues

### 1. "Try Again" and "Retreat" buttons call the same handler
**Severity:** medium
**Lines:** 199-204

Both the "Try Again" and "Retreat" buttons call `onContinue` — they do the exact same thing. Two buttons with different labels but identical behavior is confusing.

**Suggested Fix:** Either differentiate the callbacks (`onRetry` vs `onRetreat`) or remove one of the buttons. If this is unused legacy code, consider deleting the entire file.
