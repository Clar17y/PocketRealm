# Frontend Audit: Exploration

**Component Audited:** `apps/web/src/components/screens/Exploration.tsx` (406 lines)
**Date:** 2026-03-15

---

## Accessibility

### 1. Tier selector buttons lack radio/tab semantics
**Severity:** low
**Lines:** 248-262

The tier selector buttons function as a mutually exclusive selection (radio group) but have no `role="radiogroup"`/`role="radio"` or `aria-checked` attributes.

**Suggested Fix:** Wrap in `<div role="radiogroup" aria-label="Exploration tier">` and add `role="radio"` + `aria-checked={effectiveSelectedTier === tier}` to each button.

---

## Component Duplication

### 1. Turn preset buttons hardcoded instead of using TurnPresets component
**Severity:** medium
**Lines:** 307-334

Four inline buttons (100, 500, 1K, 5K) duplicate the pattern that `TurnPresets` (from `components/common/TurnPresets.tsx`) already handles. The Gathering screen uses `TurnPresets` for the same purpose. The Exploration screen hardcodes the buttons with identical styling.

**Suggested Fix:** Use `TurnPresets`:
```tsx
import { TurnPresets } from '@/components/common/TurnPresets';
// ...
<TurnPresets
  presets={[
    { label: '100', turns: Math.min(100, availableTurns) },
    { label: '500', turns: Math.min(500, availableTurns) },
    { label: '1K', turns: Math.min(1000, availableTurns) },
    { label: '5K', turns: Math.min(5000, availableTurns) },
  ]}
  currentValue={turnInvestment[0]}
  onChange={(t) => setTurnInvestment([t])}
/>
```
This eliminates ~25 lines and ensures consistent preset behavior.
