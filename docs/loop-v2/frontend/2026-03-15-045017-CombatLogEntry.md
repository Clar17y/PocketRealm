## Accessibility

### 1. Expandable row uses div onClick without keyboard support
**Severity:** medium
**Lines:** 71-74

The expandable detail row uses `<div onClick>` with `cursor-pointer` but no `role="button"`, `tabIndex`, or keyboard handler. Keyboard users can't expand combat log entries to see damage breakdowns.

**Suggested Fix:** Add `role="button"`, `tabIndex={0}`, `aria-expanded={expanded}`, and `onKeyDown` for Enter/Space:
```tsx
<div
  role={hasDetails ? 'button' : undefined}
  tabIndex={hasDetails ? 0 : undefined}
  aria-expanded={hasDetails ? expanded : undefined}
  onClick={hasDetails ? () => setExpanded(p => !p) : undefined}
  onKeyDown={hasDetails ? (e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); setExpanded(p => !p); }} : undefined}
  ...
>
```

## State Issues

### 1. Dynamic Tailwind class construction won't work with JIT
**Severity:** medium
**Lines:** 36-42

```tsx
return `text-[${ACTION_CATEGORY_COLORS[category]}]`;
```

Dynamic Tailwind class names constructed via string interpolation (e.g., `text-[var(--rpg-red)]`) are NOT detected by Tailwind's JIT compiler because they aren't present as full static strings in the source code. These classes won't be included in the generated CSS.

This works by coincidence because these same `text-[var(--rpg-...)]` classes appear as static strings elsewhere in the codebase. If those other usages were removed, these dynamic classes would silently break.

**Suggested Fix:** Use inline `style` instead of dynamic class construction:
```tsx
function getActionCategoryStyle(entry: LastCombatLogEntry): React.CSSProperties {
  if (entry.actionId && BASE_ACTION_DEFINITIONS[entry.actionId]) {
    return { color: ACTION_CATEGORY_COLORS[BASE_ACTION_DEFINITIONS[entry.actionId].category] };
  }
  // ...
}
// Usage: <span style={getActionCategoryStyle(entry)}>{entry.actionName}</span>
```
