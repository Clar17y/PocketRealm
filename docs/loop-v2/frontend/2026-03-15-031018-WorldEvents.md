# Frontend Audit: WorldEvents

**Component Audited:** `apps/web/src/components/screens/WorldEvents.tsx` (240 lines)
**Date:** 2026-03-15

---

## Accessibility

### 1. Boss encounter cards are clickable divs, not buttons
**Severity:** medium
**Lines:** 156-191

`PixelCard` with `onClick` and `cursor-pointer` renders a `<div>` that's not keyboard accessible. Users can't tab to boss encounter cards or activate them with Enter/Space.

**Suggested Fix:** Wrap in a `<button>` or add `role="button"`, `tabIndex={0}`, and keyboard handler to the PixelCard.

---

## Component Duplication

### 1. Boss HP bar duplicated from BossEncounterPanel
**Severity:** low
**Lines:** 169-183

The boss HP progress bar uses the same `w-full h-2 rounded-full` + `rgba(255,255,255,0.1)` background pattern as `BossEncounterPanel` (lines 210-218). Minor since this is a compact preview card while BossEncounterPanel is the full detail view.

---

## State Issues

### 1. `refresh` has no error handling
**Severity:** medium
**Lines:** 89-98

Both `getActiveEvents()` and `getActiveBossEncounters()` are called without try/catch. If either throws (network error), `setLoading(false)` never runs, leaving the "Loading..." state permanently.

**Suggested Fix:**
```tsx
const refresh = useCallback(async () => {
  setLoading(true);
  try {
    const [eventsRes, bossRes] = await Promise.all([
      getActiveEvents(),
      getActiveBossEncounters(),
    ]);
    if (eventsRes.data) setEvents(eventsRes.data.events);
    if (bossRes.data) setBosses(bossRes.data.encounters);
  } catch {
    // Optionally surface error to user
  } finally {
    setLoading(false);
  }
}, []);
```

## UX Issues

No issues found. Clean layout with proper event categorization (global → current zone → other zones), boss encounter cards with HP previews, refresh button, and `FeatureTutorial` onboarding. The `EventCard` sub-component is well-extracted.
