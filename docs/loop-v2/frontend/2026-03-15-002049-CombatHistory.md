## Accessibility

### 1. Search input and filter selects lack labels
**Severity:** low
**Lines:** 305-356

The search input and five `<select>` elements have no `<label>` or `aria-label`. They rely on placeholder text and first-option text for context.

**Suggested Fix:** Add `aria-label` to each:
```tsx
<input aria-label="Search combat history" ... />
<select aria-label="Sort by" ...>
<select aria-label="Filter by outcome" ...>
<select aria-label="Filter by zone" ...>
<select aria-label="Filter by mob" ...>
```

### 2. Copy button uses `title` instead of `aria-label`
**Severity:** low
**Lines:** 451-459

`title="Copy formatted log for sharing"` isn't reliably announced by screen readers.

**Suggested Fix:** Add `aria-label="Copy combat log for sharing"` to the button.

## Component Duplication

### 1. Copy-share pattern duplicated with CombatScreen
**Severity:** medium
**Lines:** 80, 286-297 (CombatHistory), vs CombatScreen lines 126, 198-210

Both components implement the same pattern:
- `copyState` state (`idle` | `copied` | `error`)
- `handleCopyShare` callback with `navigator.clipboard.writeText` + setTimeout reset
- Button with `{copyState === 'copied' ? 'Copied' : copyState === 'error' ? 'Copy failed' : 'Copy Log'}`

**Suggested Fix:** Extract a `<CopyButton text={shareText} label="Copy Log" />` component to `components/common/`:
```tsx
function CopyButton({ text, label = 'Copy' }: { text: string; label?: string }) {
  const [state, setState] = useState<'idle' | 'copied' | 'error'>('idle');
  const handleClick = async () => {
    try {
      await navigator.clipboard.writeText(text);
      setState('copied');
      setTimeout(() => setState('idle'), 1500);
    } catch {
      setState('error');
      setTimeout(() => setState('idle'), 2000);
    }
  };
  return (
    <button onClick={() => void handleClick()} disabled={!text} ...>
      {state === 'copied' ? 'Copied' : state === 'error' ? 'Copy failed' : label}
    </button>
  );
}
```
