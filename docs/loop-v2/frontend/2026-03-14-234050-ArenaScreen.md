# Frontend Audit: ArenaScreen

**Component Audited:** `apps/web/src/app/game/screens/ArenaScreen.tsx` (660 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. Tab buttons lack ARIA tab roles
**Severity:** medium
**Lines:** 347-374

The Ladder/History/Alerts/Rankings tab buttons have no `role="tablist"`, `role="tab"`, or `aria-selected`.

**Suggested Fix:** Wrap in `<div role="tablist">` and add `role="tab"` + `aria-selected={activeView === tab.id}` to each button.

### 2. Match detail expand buttons lack aria-expanded
**Severity:** low
**Lines:** 475-505

Match history items expand to show combat logs via a `<button>` with a rotating chevron, but no `aria-expanded` attribute.

**Suggested Fix:** Add `aria-expanded={isExpanded}` to the button.

### 3. Pagination buttons lack aria-label
**Severity:** low
**Lines:** 537-555

The prev/next pagination buttons show only `ChevronLeft`/`ChevronRight` icons with no `aria-label`.

**Suggested Fix:** Add `aria-label="Previous page"` and `aria-label="Next page"`.

## Component Duplication

### 1. PvP combat playback setup duplicated with FriendsScreen spar
**Severity:** medium
**Lines:** 259-287 (ArenaScreen), 409-437 (FriendsScreen)

Both screens set up `PlaybackSurface` → `CombatPlayback` with nearly identical prop wiring from a PvP/spar result object (playerMaxHp, playerStartHp, playerStartStamina, etc.). The only differences are the title ("Arena Replay" vs "Friendly Spar") and the onComplete callback.

**Suggested Fix:** Extract a `<PvPPlayback result={...} playerId={...} title="..." onDone={...} speedMs={...} />` component that handles the `PlaybackSurface` + `CombatPlayback` wiring. This eliminates ~30 lines of duplicated prop passing in each screen.

### 2. Result summary panel duplicated with FriendsScreen
**Severity:** medium
**Lines:** 289-343 (ArenaScreen), 370-394 (FriendsScreen)

Both show the same "Victory!/Defeat!/Draw!" summary card after combat playback completes. Arena adds rating change and flee outcomes, but the core pattern is identical.

**Suggested Fix:** Extract a `<PvPResultSummary result={...} playerId={...} onDismiss={...} extras={...} />` component. Pass the arena-specific fields (rating change, flee outcome, recover button) via a `children` or `extras` prop.

## State Issues

### 1. Rankings effect doesn't handle errors
**Severity:** medium
**Lines:** 155-162

```tsx
useEffect(() => {
  setRankingsLoading(true);
  void getLeaderboard('pvp_rating', rankingsAroundMe).then((res) => {
    if (res.data) setRankingsData(res.data);
    setRankingsLoading(false);
  });
}, [activeView, rankingsAroundMe]);
```

If `getLeaderboard` rejects, `setRankingsLoading(false)` never runs. The rankings tab stays in a permanent loading state.

**Suggested Fix:** Add a `.catch()` or use `try/finally` in an async IIFE:
```tsx
useEffect(() => {
  if (activeView !== 'rankings') return;
  setRankingsLoading(true);
  getLeaderboard('pvp_rating', rankingsAroundMe)
    .then((res) => { if (res.data) setRankingsData(res.data); })
    .catch(() => { /* optionally set error */ })
    .finally(() => setRankingsLoading(false));
}, [activeView, rankingsAroundMe]);
```

## UX Issues

### 1. Loading state uses plain text instead of LoadingCard
**Severity:** low
**Lines:** 607-614

Other screens use `<LoadingCard />` for loading states, but ArenaScreen shows bare text "Loading arena data..." in a raw `<div>`. Inconsistent with the rest of the app.

**Suggested Fix:** Replace with `<LoadingCard message="Loading arena data..." />`.

### 2. Error display uses inline styling instead of ErrorBanner
**Severity:** low
**Lines:** 623-627

The error display uses inline `border border-[var(--rpg-red)]` styling instead of the shared `<ErrorBanner>` component used by FriendsScreen, Quests, and others.

**Suggested Fix:** Replace with `{error && <ErrorBanner message={error} />}`.
