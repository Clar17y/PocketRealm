# Frontend Audit: Casino

**Component Audited:** `apps/web/src/components/screens/Casino.tsx` (879 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. Color-only differentiation on roulette numbers
**Severity:** medium
**Lines:** 479-497

Red and black numbers are distinguished solely by background color. Color-blind users (protanopia, deuteranopia) cannot tell red from black. No text label, pattern, or icon distinguishes them.

**Suggested Fix:** Add a subtle visual indicator — e.g., a small "R" or "B" letter badge, or use a pattern (striped vs solid) alongside color. Alternatively, add `aria-label={`${n} ${color}`}` so screen readers announce "14 red".

### 2. Corner bet buttons lack aria-label
**Severity:** medium
**Lines:** 503-523

Corner bet buttons have `title` (tooltip) but no `aria-label`. Screen readers don't reliably announce `title`. These buttons have no visible text content.

**Suggested Fix:** Replace `title` with `aria-label`:
```tsx
aria-label={`Corner bet: ${corner.numbers.join(', ')}`}
```

### 3. Exchange turns input has no associated label
**Severity:** medium
**Lines:** 402-410

The number input for turn exchange has a `placeholder` but no `<label>` element. Screen readers announce it as an unlabeled input.

**Suggested Fix:** Add a visually-hidden label:
```tsx
<label htmlFor="exchange-turns" className="sr-only">Turns to exchange</label>
<input id="exchange-turns" ... />
```
Or use `aria-label="Turns to exchange"` on the input.

### 4. Roulette phase transitions not announced
**Severity:** low
**Lines:** 429, 445-452

When the round phase changes (betting → spinning → result), there's no `aria-live` region to announce this to screen readers.

**Suggested Fix:** Wrap `RoundPhaseIndicator` in an `aria-live="polite"` container.

### 5. Spin history color pips have no text alternative
**Severity:** low
**Lines:** 748-759

Color distribution uses colored dots (`w-2.5 h-2.5 rounded-full`) with a count. The dots have no `aria-label`, so screen readers just see the count with no context.

**Suggested Fix:** Add `aria-label="Red"` / `aria-label="Black"` / `aria-label="Green"` to each pip, or use `<span className="sr-only">Red</span>`.

## Component Duplication

### 1. Hot/Cold stat lists are identical except sort order and color
**Severity:** medium
**Lines:** 776-793, 801-818

The Hot and Cold sections render the exact same structure — number badge + progress bar + count. Only the sort direction (`b.count - a.count` vs `a.count - b.count`) and bar color (`orange-400` vs `blue-400`) differ.

**Suggested Fix:** Extract a `<NumberStatList stats={...} sortDirection="desc"|"asc" barColor="orange-400"|"blue-400" />` component, reducing ~40 lines to ~10.

### 2. Outside bet button pattern repeated 3 times
**Severity:** medium
**Lines:** 528-545, 548-569, 572-594

Column, dozen, and even-money bet buttons all follow the same pattern: grid of buttons with identical selection ring styling, hover handling (`onMouseEnter`/`onMouseLeave`), and `ChipStackIndicator` rendering. The structure differs only in grid columns and data.

**Suggested Fix:** Extract a `<BetButtonRow bets={[{label, type, value, cls?}]} selectedBetType={...} selectedBetValue={...} onSelect={...} onHover={...} chipMap={...} />` component.

### 3. `colorClass` and `colorPipClass` are near-duplicates
**Severity:** low
**Lines:** 42-56

Both map the same `'red' | 'black' | 'green'` input to similar classes. `colorPipClass` is just the background portion of `colorClass`.

**Suggested Fix:** Derive `colorPipClass` from a shared color map or merge into one function with an optional `withText` flag.

## State Issues

### 1. `fetchRound` and `fetchHistory` have no error handling
**Severity:** medium
**Lines:** 226-239

Both functions call the API and silently ignore failures. If the network drops or the API errors, the roulette state goes stale with no feedback.

**Suggested Fix:** Add error handling that sets a user-visible error:
```tsx
const fetchRound = useCallback(async () => {
  try {
    const result = await api.getRouletteRound();
    if (result.data) setRoundState(result.data);
  } catch { setError('Failed to fetch roulette state'); }
}, []);
```

### 2. Polling doesn't cancel in-flight requests on unmount
**Severity:** low
**Lines:** 248-265

The polling interval is cleared on unmount, but any fetch already in progress can still call `setRoundState` after the component is gone. React 18+ suppresses the warning, but it's still wasteful.

**Suggested Fix:** Use an `AbortController` passed to the fetch, or an `ignore` flag in the effect cleanup.

### 3. Heat map toggle race condition
**Severity:** low
**Lines:** 216-221

Rapidly toggling the heat map button fires multiple `getRouletteStats()` calls. The last to resolve wins, which may not match the current toggle state.

**Suggested Fix:** Add an `ignore` flag or use the toggle state as a guard in the `.then()`:
```tsx
let ignore = false;
api.getRouletteStats().then((res) => { if (!ignore && res.data) setNumberStats(res.data.stats); });
return () => { ignore = true; };
```

## UX Issues

### 1. No loading state on initial mount
**Severity:** medium
**Lines:** 242-245

`fetchRound()` and `fetchHistory()` fire on mount but there's no loading indicator. Until the first response arrives, the user sees an empty roulette board with no indication data is loading.

**Suggested Fix:** Add a `loading` state, set it before fetches, and show a `<LoadingCard />` or skeleton while `roundState === null`.

### 2. Corner bet touch targets too small on mobile
**Severity:** medium
**Lines:** 508-517

Corner bet buttons are `w-5 h-5` (20x20px), well below the 44px minimum recommended touch target. Mobile users will struggle to accurately tap these.

**Suggested Fix:** Increase the hit area to at least `w-8 h-8` (32px) while keeping the visual indicator small using an inner element, or use a transparent padding approach:
```tsx
className="w-5 h-5 -m-1.5 p-1.5" // visual 20px, touch 32px
```

### 3. Error banner has no dismiss button
**Severity:** low
**Lines:** 384-388

Errors persist until the next action. Users can't manually dismiss them.

**Suggested Fix:** Add an `<X>` close button, or auto-dismiss after 5 seconds with `setTimeout`.
