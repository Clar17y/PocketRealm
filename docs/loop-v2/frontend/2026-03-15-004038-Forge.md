## Accessibility

### 1. SacrificePicker toggle lacks aria-expanded
**Severity:** low
**Lines:** 49-55, 82-92

## UX Issues

### 1. Forge operations have no confirmation dialog
**Severity:** high
**Lines:** 386-394, 441-448

Clicking "Upgrade Rarity" or "Reroll Bonus Stats" immediately executes without confirmation. These are among the most consequential actions in the game:
- **Upgrade failure** (without Forge Protection buff) **destroys both the target and sacrifice items**
- **Reroll** permanently replaces all bonus stats — the old stats are gone forever
- Both actions consume the sacrificial item

There's no undo and no way to recover destroyed items.

**Suggested Fix:** Use `ConfirmModal` with a danger/warning variant before each operation:
```tsx
const [confirmAction, setConfirmAction] = useState<'upgrade' | 'reroll' | null>(null);

// In the upgrade button:
onClick={() => setConfirmAction('upgrade')}

// In the render:
{confirmAction === 'upgrade' && (
  <ConfirmModal
    title="Confirm Upgrade"
    message={`Upgrade ${selected.name} to ${titleCaseRarity(nextRarity!)}? Success: ${(upgradeChance! * 100).toFixed(1)}%. On failure, ${forgeProtectionUses > 0 ? 'item is protected but sacrifice is consumed.' : 'BOTH items are destroyed.'}`}
    variant={forgeProtectionUses > 0 ? 'warning' : 'danger'}
    confirmLabel="Upgrade"
    onConfirm={async () => { setConfirmAction(null); /* existing upgrade logic */ }}
    onCancel={() => setConfirmAction(null)}
  />
)}
```
The message should clearly state the success chance, protection status, and consequences of failure.

### 2. Upgrade cost display has deeply nested ternaries
**Severity:** low
**Lines:** 343-351

The cost rendering logic has 4 nested branches handling tax, skill discount, and base cost combinations. While functional, the JSX is dense and hard to maintain.

**Suggested Fix:** Extract a `formatForgeCost(baseCost, discountedCost, inflatedCost)` helper function that returns a JSX fragment, simplifying the render logic.
