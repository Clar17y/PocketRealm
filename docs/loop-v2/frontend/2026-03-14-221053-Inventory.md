# Frontend Audit: Inventory

**Component Audited:** `apps/web/src/components/screens/Inventory.tsx` (1,046 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. Backpack/Stash tab buttons lack ARIA tab roles
**Severity:** medium
**Lines:** 304-328

The Backpack/Stash tab switcher uses styled `<button>` elements but has no `role="tablist"`, `role="tab"`, or `aria-selected`. Screen readers can't identify this as tab navigation.

**Suggested Fix:** Wrap in `<div role="tablist">`, add `role="tab"` and `aria-selected={activeTab === 'backpack'}` to each button.

### 2. Modal close buttons lack aria-label
**Severity:** medium
**Lines:** 502-507, 727-732

Both the stash item modal and item detail modal use an `<X>` icon button with no `aria-label`. Screen readers announce these as unlabeled buttons.

**Suggested Fix:** Add `aria-label="Close"` to both close buttons:
```tsx
<button aria-label="Close" onClick={...}>
  <X size={20} />
</button>
```

### 3. Batch checkbox overlays lack checkbox role
**Severity:** medium
**Lines:** 472-477, 666-671

`BatchCheckboxOverlay` and `BatchDimOverlay` provide visual selection cues but no `role="checkbox"` or `aria-checked`. Screen reader users can't determine selection state.

**Suggested Fix:** Add `role="checkbox"` and `aria-checked={isSelected}` to the overlay, or better yet, add `aria-pressed={isSelected}` to the `ItemCard` button itself when in batch mode.

### 4. Empty inventory slots exposed to screen readers
**Severity:** low
**Lines:** 676-681

Empty slot divs are announced as empty elements. They're decorative and should be hidden.

**Suggested Fix:** Add `aria-hidden="true"` to the empty slot div.

## Component Duplication

### 1. Batch action handler pattern repeated 6 times
**Severity:** medium
**Lines:** 344-355, 367-377, 390-400, 549-557, 566-574, 588-596

Every batch action follows the same structure:
```tsx
async () => {
  if (!onApiFn) return;
  batch.setBusy(true);
  try {
    await onApiFn([...batch.selection]);
    batch.reset();
    await loadStash(); // only for stash actions
  } finally { batch.setBusy(false); }
}
```

**Suggested Fix:** Extract a helper:
```tsx
const runBatch = (batch: ReturnType<typeof useBatchMode>, fn: (ids: string[]) => Promise<void>, refreshStash = false) =>
  async () => {
    batch.setBusy(true);
    try { await fn([...batch.selection]); batch.reset(); if (refreshStash) await loadStash(); }
    finally { batch.setBusy(false); }
  };
```
Then use: `onAction={runBatch(salvageBatch, onSalvageBatch!)}`

### 2. Stat grid rows repeat identical JSX structure
**Severity:** medium
**Lines:** 766-836

Seven stat rows (attack, armor, magicDefence, health, dodge, accuracy, inventorySlots) all share the same template: `Icon + label + formatted value`. The `statDisplay()` function (line 85-96) already provides `Icon`, `color`, `label` but isn't used to drive a loop.

**Suggested Fix:** Define base stats as an array and render in a loop:
```tsx
const BASE_STATS = ['attack', 'armor', 'magicDefence', 'health', 'dodge', 'accuracy'] as const;
// ...
{BASE_STATS.map(stat => {
  const val = numStat(stats[stat]);
  if (typeof val !== 'number' || val === 0) return null;
  const { Icon, color, label } = statDisplay(stat);
  return <StatRow key={stat} Icon={Icon} color={color} label={label} stat={stat} value={val} />;
})}
```
This reduces ~70 lines to ~10.

### 3. Backpack and stash item grids share identical rendering logic
**Severity:** medium
**Lines:** 444-481, 636-674

Both grids render `grid grid-cols-6 gap-2`, iterate items, compute `isSelectable`/`isSelected` from batch modes, and render `ItemCard` + `BatchCheckboxOverlay`/`BatchDimOverlay` in the same structure. The only differences are the data source and which batch modes are checked.

**Suggested Fix:** Extract an `<ItemGrid items={...} batchModes={...} onItemClick={...} />` component that takes items and active batch modes as props.

### 4. Rarity-to-border-color mapping is inline
**Severity:** low
**Lines:** 696-705

The rarity → color ternary chain could be a shared `rarityColor(rarity)` utility usable across ItemCard, Forge, and other components.

## State Issues

### 1. `loadStash` has empty deps but uses `getSalvageCost` from props
**Severity:** medium
**Lines:** 144-169

```tsx
const loadStash = useCallback(async () => {
  // ...
  salvageCost: isEquip && getSalvageCost ? getSalvageCost(item.template.id) : null,
  // ...
}, []);  // getSalvageCost not in deps
```

If `getSalvageCost` changes (e.g., after crafting recipes reload changes discount rates), the stash items will show stale salvage costs until the stash tab is re-opened.

**Suggested Fix:** Add `getSalvageCost` to the dependency array:
```tsx
}, [getSalvageCost]);
```

### 2. Reset functions not stable across renders
**Severity:** low
**Lines:** 135, 142

`resetAllBackpackModes` and `resetAllStashModes` create new closures each render. They're called inside effects (line 180-186) but the effect uses eslint-disable to suppress the warning. If these functions are ever passed as props, this could cause unnecessary re-renders.

**Suggested Fix:** Wrap in `useCallback` or extract into the `useBatchMode` hook as a group-reset utility.

## UX Issues

### 1. Batch actions have no error handling
**Severity:** medium
**Lines:** 344-400, 549-596

All six batch action handlers catch nothing — if the API call rejects, the promise is unhandled. The batch mode resets to idle (via `finally`) but the user gets no error feedback.

**Suggested Fix:** Add a try/catch that surfaces the error:
```tsx
try {
  await onApiFn([...batch.selection]);
  batch.reset();
} catch (err) {
  // Show error to user — use setActionError or a local error state
} finally {
  batch.setBusy(false);
}
```

### 2. Hard-coded repair costs in button text
**Severity:** medium
**Lines:** 894

```tsx
{selectedItem.durability.current <= 0 ? 'Fix (150)' : 'Repair (100)'}
```

Repair turn costs are hardcoded in the UI string. If `CRAFTING_CONSTANTS.REPAIR_TURN_COST` or `CRAFTING_CONSTANTS.FIX_BROKEN_TURN_COST` change, the button text would be wrong.

**Suggested Fix:** Import the constants and use them:
```tsx
`Fix (${CRAFTING_CONSTANTS.FIX_BROKEN_TURN_COST})` : `Repair (${CRAFTING_CONSTANTS.REPAIR_TURN_COST})`
```

### 3. Stash load error silently swallowed
**Severity:** low
**Lines:** 144-168

If `getStash()` throws, the `finally` block clears loading state but no error is shown. The stash tab just appears empty with no indication of failure.

**Suggested Fix:** Add a `stashError` state, set it in a `catch` block, and display it in the stash tab UI.
