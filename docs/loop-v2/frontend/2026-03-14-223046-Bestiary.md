# Frontend Audit: Bestiary

**Component Audited:** `apps/web/src/components/screens/Bestiary.tsx` (819 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. View tab buttons lack ARIA tab roles
**Severity:** medium
**Lines:** 508-524

The Monsters/Expeditions/Bosses/Prefixes tab buttons have no `role="tablist"`, `role="tab"`, or `aria-selected`.

**Suggested Fix:** Wrap in `<div role="tablist">`, add `role="tab"` and `aria-selected={activeView === view}` to each button.

### 2. Three modal close buttons lack aria-label
**Severity:** medium
**Lines:** 290-292, 417-419, 644-649

All three detail modals use `<X>` icon buttons with no `aria-label`. Screen readers announce them as unlabeled.

**Suggested Fix:** Add `aria-label="Close"` to each close button.

### 3. Prefix pip dots rely on color-only differentiation
**Severity:** low
**Lines:** 79-94

The prefix pip indicators use gold/blue/gray dots with only a `title` tooltip (not reliably announced). Screen readers get no indication of status.

**Suggested Fix:** Add `aria-label={found ? prefix : 'Not found'}` to each pip, or ensure the summary text `{count}/{TOTAL_PREFIXES}` provides sufficient context.

## Component Duplication

### 1. Three detail modals share near-identical structure
**Severity:** high
**Lines:** 271-336 (ExpeditionBestiaryTab), 399-463 (WorldBossBestiaryTab), 608-812 (main Bestiary)

All three modals follow the same pattern:
- `ModalOverlay` → `PixelCard` → header (image + name + X button) → stats → rotation → close button

The expedition and world boss modals are especially similar — identical header layout, identical close button placement, identical stats rendering, identical rotation rendering.

**Suggested Fix:** Extract a `<BestiaryDetailModal>` component that takes:
- `name`, `imageSrc`, `onClose`
- `stats?: { label, icon, value, color }[]`
- `rotation?: { round, actionName, targetMode, isTelegraphed? }[]`
- `children` for modal-specific content (drops, prefixes, etc.)

This would replace ~300 lines of duplicated JSX across the three modals.

### 2. Rotation display duplicated between expedition and world boss modals
**Severity:** medium
**Lines:** 315-330, 442-457

Both render the exact same `R{round}` + `actionName` + `(AoE/Single)` row structure. The only difference: world boss adds `isTelegraphed` font styling.

**Suggested Fix:** Extract a `<RotationDisplay rotation={...} />` component that handles the `isTelegraphed` styling conditionally. Use it in all three modals (including main bestiary at lines 773-794).

### 3. Stats display (Icon + label + value) repeated across modals
**Severity:** medium
**Lines:** 296-310, 426-437, 662-707

Three separate renderings of stat rows with Heart/Sword/Shield icons. The main bestiary adds kill-count gating, but the core `Icon + stat name + value` template is identical.

**Suggested Fix:** Extract a `<StatRow icon={...} label="HP" value={stats.hp} color="var(--rpg-green-light)" hidden={!showHP} />` component and render stats from a data array.

### 4. Monster/mob grid card shared between expedition and main bestiary
**Severity:** medium
**Lines:** 213-253, 534-604

Both render a grid of clickable cards with discovered (image + name + kill count) and undiscovered (placeholder + "???") states. The structure and styling are nearly identical.

**Suggested Fix:** Extract a `<MonsterGrid mobs={...} onSelect={...} />` component that handles both discovered and undiscovered rendering.

## State Issues

### 1. `sortedMonsters` not memoized
**Severity:** low
**Lines:** 471

```tsx
const sortedMonsters = [...monsters].sort((a, b) => Number(b.isDiscovered) - Number(a.isDiscovered));
```

Creates a new sorted array every render. Should use `useMemo` since `monsters` rarely changes.

**Suggested Fix:**
```tsx
const sortedMonsters = useMemo(
  () => [...monsters].sort((a, b) => Number(b.isDiscovered) - Number(a.isDiscovered)),
  [monsters]
);
```
