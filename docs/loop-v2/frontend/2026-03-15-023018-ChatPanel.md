# Frontend Audit: ChatPanel

**Component Audited:** `apps/web/src/components/ChatPanel.tsx` (279 lines)
**Date:** 2026-03-15

---

## Accessibility

### 1. Channel tab buttons lack ARIA tab roles
**Severity:** low
**Lines:** 116-162

The World/Zone/Casino tab buttons have no `role="tablist"`, `role="tab"`, or `aria-selected`. Lower severity since the chat panel is a secondary overlay feature.

**Suggested Fix:** Wrap the tab row in `<div role="tablist">` and add `role="tab"` + `aria-selected` to each channel button.

### 2. Chat messages region lacks aria-live
**Severity:** low
**Lines:** 189-238

The messages container doesn't use `aria-live="polite"`. New incoming messages won't be announced by screen readers. Minor since live chat is primarily a visual feature.

**Suggested Fix:** Add `aria-live="polite"` and `aria-label="Chat messages"` to the messages container div.

---

## Component Duplication

### 1. Channel tab button styling repeated 3 times
**Severity:** low
**Lines:** 117-130, 132-145, 148-161

Three tab buttons use the same active/inactive class string:
```
bg-[var(--rpg-gold)]/20 text-[var(--rpg-gold)] border border-[var(--rpg-gold)]/40
```
vs
```
text-[var(--rpg-text-secondary)] hover:text-[var(--rpg-text-primary)]
```

Each also has the identical unread badge pattern.

**Suggested Fix:** Extract a `<ChatTab channel={...} label={...} unread={...} active={...} onClick={...} />` component to reduce ~40 lines of duplication to ~10.

---

## State Issues

No issues found. State management is clean — `input` is local, `pinnedDismissed` resets on new pin ID, and auto-scroll/focus effects are properly scoped.

---

## UX Issues

No issues found. Good use of `aria-label` on the open/close/send buttons, auto-focus on panel open, auto-scroll on new messages, rate limit error display, and pinned message banner with dismiss. The floating button with unread badge is a standard chat pattern.
