# Frontend Audit: Settings

**Component Audited:** `apps/web/src/components/screens/Settings.tsx` (222 lines)
**Date:** 2026-03-15

---

## Accessibility

### 1. Slider labels not programmatically linked
**Severity:** low
**Lines:** 87-97, 128-138, 142-152

The descriptive text ("Combat Log Speed", "Exploration Playback Speed", "Default Explore Turns") is plain `<p>` text above each `<Slider>`, not a `<label>` linked via `htmlFor`/`id`. Screen readers can't associate the label with the slider control.

**Suggested Fix:** Add `aria-label` to each `Slider` component, e.g. `aria-label="Combat log speed"`.

---

## Component Duplication

### 1. Speed slider + label pattern repeated twice
**Severity:** low
**Lines:** 86-98, 127-138

Both combat and exploration speed sections use the same layout: `<p>` label + `<Slider>` + `<span>` with `speedLabel()`. Minor — only two instances, and the labels/callbacks differ.

---

## State Issues

No issues found. This is a pure presentational component — all state lives in the parent (`usePlayerSettings` hook). No local state, no effects, no async operations.

---

## UX Issues

No issues found. Clean settings layout with logical grouping (Combat, Exploration, Recovery, Crafting, Inventory, Account), clear descriptions for each option, and proper use of `ToggleSwitch`, `Slider`, and `RaritySelector` shared components.
