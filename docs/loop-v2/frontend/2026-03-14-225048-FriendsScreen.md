# Frontend Audit: FriendsScreen

**Component Audited:** `apps/web/src/components/screens/FriendsScreen.tsx` (712 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. Online status indicator is color-only with no text alternative
**Severity:** medium
**Lines:** 527-534

The green/gray dot (`w-2 h-2 rounded-full`) indicates online/offline status via color only. No `aria-label`, no `sr-only` text. Screen readers and color-blind users get no indication.

**Suggested Fix:** Add a screen-reader-only label:
```tsx
<span className="sr-only">{f.isOnline ? 'Online' : 'Offline'}</span>
<span className="..." style={{ backgroundColor: f.isOnline ? '...' : '...' }} aria-hidden="true" />
```

### 2. Friend list cards are clickable divs, not keyboard accessible
**Severity:** medium
**Lines:** 518-567

`PixelCard` with `onClick` renders a `<div>` that's not focusable or operable via keyboard. Users can't tab to friend cards or open the profile modal with Enter/Space.

**Suggested Fix:** Either render PixelCard as a `<button>` (via an `as` prop or wrapper), or add `role="button"`, `tabIndex={0}`, and an `onKeyDown` handler for Enter/Space.

### 3. Search input has no associated label
**Severity:** low
**Lines:** 445-458

The "Add Friend" heading is a `<p>` that isn't linked to the input. The input relies on `placeholder` only.

**Suggested Fix:** Add `aria-label="Search username"` to the input, or use `<label htmlFor="friend-search">` with a matching `id`.

## Component Duplication

### 1. Incoming and outgoing request cards nearly identical
**Severity:** medium
**Lines:** 583-618, 632-657

Both render `PixelCard` → `username + level + relativeTime` → action buttons. The layout is identical — only the button set differs (Accept/Decline vs Cancel).

**Suggested Fix:** Extract a `<RequestCard request={r} actions={...} actionBusy={actionBusy} />` component:
```tsx
function RequestCard({ request, actions, actionBusy }: {
  request: FriendRequest;
  actions: { label: string; variant: string; onClick: () => void }[];
  actionBusy: boolean;
}) { ... }
```
This eliminates ~40 lines of duplication.

## State Issues

### 1. `loadFriends` sets `loading=true`, causing full-screen flash after actions
**Severity:** medium
**Lines:** 92-107, 212, 252, 272

After accepting a request (`handleAccept`) or removing a friend (`handleUnfriend`), the code calls `loadFriends()` which sets `loading = true`. Since the `loading` guard at line 355 replaces the entire screen with `<LoadingCard />`, this causes a jarring full-screen flash on every action.

**Suggested Fix:** Split initial load from refresh. Add a `hasLoaded` ref and only show the full-screen spinner on initial mount:
```tsx
const hasLoaded = useRef(false);
const loadFriends = useCallback(async () => {
  if (!hasLoaded.current) setLoading(true);
  // ...fetch...
  hasLoaded.current = true;
  setLoading(false);
}, []);
```
Or: only call `setLoading(true)` in the `useEffect` initial load, not in `loadFriends` itself.

### 2. `sortedFriends` not memoized
**Severity:** low
**Lines:** 335-338

```tsx
const sortedFriends = [...friends].sort(...)
```

Creates a new sorted array on every render. Minor since friend lists are small.

**Suggested Fix:** Wrap in `useMemo(() => [...friends].sort(...), [friends])`.

## UX Issues

### 1. Remove friend has no confirmation dialog
**Severity:** medium
**Lines:** 543-553

Clicking "Remove" immediately calls `handleUnfriend()` with no confirmation. Removing a friend is a socially significant action.

**Suggested Fix:** Add a confirmation dialog using `ConfirmModal`:
```tsx
<ConfirmModal
  title="Remove Friend?"
  message={`Remove ${f.username} from your friends list?`}
  variant="danger"
  onConfirm={() => handleUnfriend(f.friendshipId)}
  onCancel={...}
/>
```

### 2. Block player has no confirmation dialog
**Severity:** medium
**Lines:** 554-564

Clicking "Block" immediately blocks the player and removes the friendship. This is even more destructive than unfriending — it should definitely require confirmation.

**Suggested Fix:** Same pattern as above with `ConfirmModal`, using variant "danger" and messaging about both blocking and friendship removal.

### 3. Loading flash after every friend action
**Severity:** medium
**Lines:** 355-363

As noted in State Issues, every friend action triggers a full-screen loading spinner replacement. This is particularly jarring because the action buttons (Accept/Decline/Remove/Block) are at the bottom of individual cards, but the feedback replaces the entire screen.

**Suggested Fix:** See State Issue #1 fix. Alternatively, keep the current list visible and show a per-card loading indicator.
