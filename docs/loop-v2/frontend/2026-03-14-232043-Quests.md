# Frontend Audit: Quests

**Component Audited:** `apps/web/src/components/screens/Quests.tsx` (695 lines)
**Date:** 2026-03-14

---

## Accessibility

### 1. Reroll button uses `title` instead of `aria-label`
**Severity:** low
**Lines:** 132-139

The reroll button has `title="Reroll quest"` but no `aria-label`. Screen readers don't reliably announce `title` attributes. The button's only visible content is a `RefreshCw` icon.

**Suggested Fix:** Replace `title` with `aria-label`:
```tsx
<button aria-label="Reroll quest" ... >
```

### 2. Progress bar lacks ARIA progressbar role
**Severity:** low
**Lines:** 71-76

`QuestProgressBar` is a visual-only progress div. The numeric text above (`current / max`) provides context, but the bar itself has no `role="progressbar"`.

**Suggested Fix:** Add `role="progressbar"` + `aria-valuenow={current}` + `aria-valuemax={max}` to the outer bar div.

### 3. Shop target select lacks label
**Severity:** low
**Lines:** 282-291

The `<select>` for item targets (zone, monster, contract) has no `<label>` or `aria-label`. The placeholder option provides some context.

**Suggested Fix:** Add `aria-label={targetPlaceholder ?? 'Select target'}` to the select.

## Component Duplication

### 1. Quest token balance card duplicated
**Severity:** medium
**Lines:** 466-476 (ShopTab), 607-616 (Quests)

Both the Shop tab and the Quests tab render identical token balance cards — same `Coins` icon, "Quest Tokens" label, and formatted balance. The structure is copy-pasted.

**Suggested Fix:** Extract a `<TokenBalanceCard tokens={n} />` component:
```tsx
function TokenBalanceCard({ tokens }: { tokens: number }) {
  return (
    <PixelCard padding="sm">
      <div className="flex items-center gap-2">
        <Coins size={20} color="var(--rpg-gold)" />
        <div>
          <div className="text-xs text-[var(--rpg-text-secondary)]">Quest Tokens</div>
          <div className="text-lg font-bold text-[var(--rpg-gold)] font-mono">{tokens.toLocaleString()}</div>
        </div>
      </div>
    </PixelCard>
  );
}
```

## State Issues

### 1. Shop `tokens` state diverges from parent
**Severity:** medium
**Lines:** 322, 339, 392

`ShopTab` copies `questTokens` prop into local state (`useState(questTokens)`) and updates it locally on purchase (`setTokens(res.data.newBalance)`). If the parent's `questState.questTokens` changes independently — e.g., the player earns tokens from completing a quest while the shop is open — the shop balance shows the stale initial value.

**Suggested Fix:** Either lift the token balance to the parent and pass it down reactively, or sync local state when the prop changes:
```tsx
useEffect(() => {
  setTokens(questTokens);
}, [questTokens]);
```

### 2. Purchase message doesn't type success vs error
**Severity:** low
**Lines:** 327, 393, 401, 404

`purchaseMessage` is a plain string used for both success ("Purchased X!") and error ("Purchase failed") messages. There's no way to style them differently.

**Suggested Fix:** Change to `{ text: string; ok: boolean } | null` (like `useAdminAction`'s `msg`):
```tsx
const [purchaseMessage, setPurchaseMessage] = useState<{ text: string; ok: boolean } | null>(null);
// Success: setPurchaseMessage({ text: `Purchased ${item.name}!`, ok: true });
// Error: setPurchaseMessage({ text: res.error.message, ok: false });
```

## UX Issues

### 1. Purchase feedback doesn't distinguish success from error
**Severity:** medium
**Lines:** 482-486

Both successful purchases and errors display in the same neutral `text-[var(--rpg-text-secondary)]` style. Users have no visual cue whether the action succeeded or failed.

**Suggested Fix:** After implementing State Issue #2:
```tsx
{purchaseMessage && (
  <div className={`text-xs text-center py-1 ${purchaseMessage.ok ? 'text-[var(--rpg-green-light)]' : 'text-[var(--rpg-red)]'}`}>
    {purchaseMessage.text}
  </div>
)}
```
