# Frontend Audit: GuildSettings

**Date:** 2026-03-15

## Accessibility

### 1. Form labels not linked to inputs
**Severity:** low
**Lines:** 173-214

Four `<label>` elements (Recruitment Mode, Tax Rate, Min Level, Description) are not linked to their inputs via `htmlFor`/`id`. Clicking the label doesn't focus the input.

**Suggested Fix:** Add matching `htmlFor`/`id` pairs to each label/input set.

---

## Component Duplication

No issues found. The `JoinRequestsSection` is well-extracted as a sub-component. The form pattern is specific to guild settings.

---

## State Issues

No issues found. Clean state management — local form state with proper save handling, error surfacing via `setError` prop, and try/catch/finally on all async actions.

## UX Issues

### 1. Disband uses double native `confirm()` instead of `ConfirmModal`
**Severity:** low
**Lines:** 146-147

The disband action uses two consecutive `window.confirm()` dialogs. While the double confirmation is appropriate for this destructive action, native dialogs are inconsistent with the themed `ConfirmModal` used elsewhere.

**Suggested Fix:** Replace with a single `ConfirmModal` with variant "danger" and strong warning text. The double-confirm intent can be preserved by requiring the user to type the guild name to confirm.
