## Findings

### Type Safety
- [high] **`(prisma as any).playerQuestState.upsert(...)` (line 568)** — Full Prisma client cast to `any` to access the `playerQuestState` model. All fields in the `create`/`update` clauses lose type checking. Same systemic ungenerated-model issue seen in buffService, cacheLootService, chestService, questShopService, xpService. — **Suggested fix:** Run `prisma generate` to add `playerQuestState` to the client type.
- [medium] **`Record<string, unknown>` bypasses Prisma update types (line 158)** — The `data` object for `prisma.player.update()` is typed as `Record<string, unknown>` and conditionally populated (lines 159-160). This completely bypasses Prisma's `PlayerUpdateInput` type checking — misspelled fields or wrong value types would not be caught at compile time. — **Suggested fix:** Type `data` as `Prisma.PlayerUpdateInput` or build the update object inline.
- [low] **4 `as` casts on item template properties (lines 207-210)** — `template.itemType as ItemType`, `rarity as ItemRarity`, `template.baseStats as ItemStats | null`, `template.slot as EquipmentSlot | null`. The `rarity` is Zod-validated so it's safe; the others narrow Prisma `string`/`JsonValue` to shared union types. Standard pattern. — **Suggested fix:** Acceptable; consider validated helpers for `baseStats` JSON.
- [low] **`bonusStats as unknown as Prisma.InputJsonObject` double cast (line 220)** — Standard JSON storage pattern. — **Suggested fix:** Acceptable.
- [low] **`ALL_SKILLS as [string, ...string[]]` casts for Zod `z.enum()` (lines 76, 95)** — Required because Zod's `z.enum()` demands a non-empty readonly tuple. — **Suggested fix:** Acceptable Zod pattern.

### Error Handling
- [medium] **Multi-step bot creation without transaction in `/expedition/fill` (lines 667-754)** — Each bot requires 7+ sequential DB operations: `player.create`, `guildMember.create`, `turnBank.create`, `playerStats.create`, `playerSkill.createMany`, `combatTemplate.create`+`combatTemplateSlot.createMany`, `addStackableItem`, `guildExpeditionMember.create`. If any step fails mid-loop, orphaned partial records remain (e.g., a bot player exists without skills or expedition membership). The loop creates `botsNeeded` bots sequentially, compounding the risk. — **Suggested fix:** Wrap the entire loop (or each bot's creation) in a `prisma.$transaction()`.
