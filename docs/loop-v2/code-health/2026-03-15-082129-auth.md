## Findings

### Type Safety
- [medium] **No Zod validation on `/refresh` and `/logout` request bodies (lines 211, 272)** — Both endpoints destructure `req.body` directly (`const { refreshToken } = req.body`). Since Express's `req.body` is typed as `any`, `refreshToken` is implicitly `any`. The `/register` and `/login` endpoints correctly use Zod schemas, but these two do not. — **Suggested fix:** Add a `refreshSchema = z.object({ refreshToken: z.string() })` and parse in both endpoints.

### Error Handling
- [medium] **Registration creates player then seeds related records without a transaction (lines 80-129)** — `prisma.player.create()` (line 80) succeeds, then 5 sequential steps run outside a transaction: `ensureEquipmentSlots` (107), `prisma.item.create` (108), `prisma.playerEquipment.upsert` (119), `ensureStarterDiscoveries` (126), `ensureStarterEncounterAndNodes` (129). If any step fails, the player exists but is incomplete — missing equipment slots, starter items, zone discoveries, or encounter sites. A retry of `/register` would fail with `USER_EXISTS` (409), leaving the player in a broken state. — **Suggested fix:** Wrap the entire registration flow in `prisma.$transaction()`, or add an idempotent repair path that re-runs failed setup steps on next login.
