# Adaptive Combat Stances: Dynamic Defence-Offense Tradeoffs

**Category:** feature
**Priority:** high
**Scope:** medium

## Description

Add a "Stance" combat action that lets players shift between three postures mid-fight -- Aggressive, Balanced, and Defensive -- each reallocating their combat stats in real-time rather than adding flat buffs. Aggressive stance sacrifices 40% of the player's defence reduction (computed via the existing `defence / (defence + 100)` curve) and converts it into a flat damage multiplier (+15% damage), while Defensive stance sacrifices 20% of accuracy and grants a proportional boost to the defence constant (effectively shifting the `+100` denominator to `+130`, making armour more efficient). Balanced is the default with no modifiers. Stance persists across rounds until changed, and switching costs one combat turn (the action itself), creating a timing puzzle: do you open aggressive to burst a low-armour mob, then swap to defensive when your HP dips, accepting one wasted turn? The key design insight is that stances interact non-linearly with the diminishing returns defence formula -- a high-defence tank gains relatively less from Defensive stance (they're already on the flat part of the curve) but loses more from Aggressive stance, while a glass-cannon mage barely notices the Defensive sacrifice but gets outsized benefit from the accuracy-to-defence conversion. This creates emergent build diversity within a single fight, not just across template configurations. Implementation adds a `stance` field to the per-round combatant state (defaulting to `'balanced'`), a new `change_stance` combat action in `combatActionDefinitions.ts`, and a pre-damage modifier pass in `calculateFinalDamage` that reads the active stance before applying defence reduction. Stances can be assigned to conditional template slots ("switch to Defensive when HP below 40%"), giving the template system a new dimension of expressiveness without adding mechanical complexity -- it reuses the existing conditional logic and stat pipeline, just rearranging how existing numbers flow through the damage formula.
